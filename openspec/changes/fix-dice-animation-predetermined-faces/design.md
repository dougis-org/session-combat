## Goals / Non-Goals

### Goals

- The physical dice in the 3D animation settle showing the predetermined faces
  for the roll, for every supported die type and for percentile, because the new
  engine natively honors `@` forced notation.
- `roll()`'s settled `DiceResults` are inspected and reconciled against the
  predetermined faces as a cheap sanity check; a mismatch (expected rare) is a
  transient per-roll condition that never latches the whole session to the
  instant path.
- The engine swap is invisible to `GlobalDiceFab` and the overlay: the
  `DiceAnimation` contract, the bounded phases, the failure split, and the modal
  gating are all preserved.
- The animated dice stay legible at 375px; the existing per-die readout gains a
  `+N more` affordance above the 15-die cap.
- E2E coverage asserts settled die faces (not just the aggregate total).
- No change to `built.total` / `built.rolls` / `built.breakdown`; no new
  randomness or network; engine + assets self-hosted and lazy-loaded.

### Non-Goals

- Cross-client frame accuracy.
- Animating more than 15 dice.
- New themes, sound, or camera work; changing `disableAnimation` resolution.
- Non-WebGL animation.
- Forking / vendoring the engine source (use the published package + copied
  assets).

## Decisions

### Decision 1: Confirm `@drdreo/dice-box-threejs` forced faces + teardown with a bounded spike before rewriting the hook

- Chosen: The first implementation task is a time-boxed spike that installs the
  package (done during propose) and drives it in a Playwright page (real WebGL)
  to confirm:
  1. `roll("Nd<sides>@v1,v2,…")` lands each physical die on its `@` value for
     `d4/d6/d8/d10/d12/d20`, with `reason: "forced"` in the returned
     `DiceResults`.
  2. `roll("2d10@t,o")` lands both percentile d10s, including a `0`/`10` face.
  3. Multi-group `"2d20@14,2+1d6@5"` returns one `DiceSet` per group with the
     forced values.
  4. `clearDice()` + dropping the instance reference stops the render loop and
     frees the WebGL context (roll → clear → new instance → roll again works
     within one page).
  5. The `assetPath` config resolves `textures/…` against a `public/`-served
     path.
- Fallback: if forced faces prove unreliable, revert to the previous plan's
  Decision 4 (detect + skip; `toDiceBoxNotation` emits plain random notation;
  every roll reconciled and mismatches skip to the instant reveal) and update
  `proposal.md` / `design.md` / `specs` / `tasks` per Change Control before E2.
- The spike is a throwaway `*.spike.test.ts` / scratch Playwright script, deleted
  before the final commit. Its outcome is recorded as a note appended to this
  design's "Open Questions" resolution.
- Rationale: The previous version of this change assumed the wrong engine had a
  forced-face feature; guessing produced the bug. Verify end-to-end first.
- Trade-offs: Adds a spike step; bounded to keep momentum.

### Decision 2: Rewrite `useDiceAnimation` against the new engine API; keep the `DiceAnimation` contract byte-for-byte

- Chosen: The hook keeps its exported `DiceAnimation` interface (`status`,
  `run(built, container): Promise<boolean>`, `teardown()`), its `runIdRef`
  single-instance invariant, its once-per-mount `loggedRef` guard, its WebGL
  probe (`webglOkRef`), and its three bounded phases. Only the engine calls
  change:
  - lazy `import('@drdreo/dice-box-threejs')` under `IMPORT_TIMEOUT_MS`.
  - `new DiceBox(container, { assetPath: ASSET_PATH, baseScale:
    diceAnimationScale(animatedDiceCount(built)), theme_material, sounds: false,
    shadows, iterationLimit })` — the constructor accepts the `HTMLElement`
    directly, so the `container.id` dance is no longer required (keep assigning an
    id anyway for the overlay's stable selector).
  - `await withTimeout(box.initialize(), INIT_TIMEOUT_MS)`.
  - `const results = await withTimeout(box.roll(toDiceBoxNotation(built)),
    ROLL_TIMEOUT_MS)` — the return value is **captured**, not discarded.
  - `box.clearDice()` wherever `box.clear()` was called (teardown, stale-run
    cleanup, per-roll failure).
- Failure classification is unchanged: import/init failure or WebGL-unavailable →
  persistent (`markUnsupported`, `status: 'unsupported'`, log once, `run()` →
  `false`); a thrown `roll()` or `ROLL_TIMEOUT_MS` → transient (drop the box,
  `console.error`, `run()` → `true` if still current).
- Alternatives considered:
  - Change the `DiceAnimation` contract to surface `DiceResults` to
    `GlobalDiceFab`: rejected — reconciliation belongs in the hook (single-engine
    invariant, n140); the Fab only needs `boolean`.
  - Keep a compatibility shim (`DiceBoxLike` with `init`/`clear`): rejected —
    the new API is close enough to inline directly; a shim just hides the swap.
- Rationale: A contained blast radius; `GlobalDiceFab` / overlay tests stay
  green.
- Trade-offs: `useDiceAnimation.test.ts` mocks are rewritten for the new mock
  surface (`initialize` / `roll` returning `DiceResults` / `clearDice`).

### Decision 3: Reconcile `roll()`'s `DiceResults` against the predetermined faces (cheap sanity check)

- Chosen: Add a pure `reconcileDiceFaces(expected, settled)` module. `expected`
  is the capped `breakdown` (or the two percentile d10 faces) grouped by die
  size; `settled` is flattened from `DiceResults.sets[].rolls[]`. Compare **per
  die-size group as an unordered multiset** over the first `animatedDiceCount()`
  dice of each group, to tolerate engine reordering. Percentile faces are
  normalized (`0 ↔ 10`) before comparison. Returns `match | mismatch`.
  - Match → `run()` resolves as today (`true`, reveal the modal normally).
  - Mismatch → **transient per-roll failure** (same class as a thrown `roll()`):
    `console.warn` once per mounted hook with a message distinct from the
    malformed-roll `console.error` and the persistent-unsupported `console.warn`;
    `clearDice()` without bumping the run token; resolve `run()` `true` so
    `GlobalDiceFab` reveals promptly (not via the long fallback); `status` stays
    `idle` — the next roll still attempts 3D.
  - With the new engine honoring `@`, a match is the overwhelming common case;
    the guard is defense-in-depth (engine regression, asset failure that yields a
    partial result, a `reason !== "forced"` die), not the primary mechanism.
- Alternatives considered:
  - Trust `reason: "forced"` on every die and skip value comparison: rejected —
    comparing the actual values is strictly stronger and nearly free.
  - Positional comparison: rejected — the engine may return groups/dice in a
    different order.
  - Latch `unsupported` on mismatch: rejected — a mismatch is per-roll, not an
    engine capability loss.
- Rationale: Uses data the library already returns; makes "we showed a wrong
  tumble" impossible with no extra awaits.
- Trade-offs: A correct-but-unusual settle could trip the guard; mitigated by
  multiset comparison and by comparing only the first `animatedDiceCount()` dice
  per group. Failure mode is always "skip to correct result", never "show wrong
  result".

### Decision 4: Retune `diceAnimationScale` for `baseScale` units; keep the curve shape

- Chosen: Keep `diceAnimationScale(count)` — `DICE_BASE_SCALE` for `count <= 6`,
  monotonic non-increasing linear ramp to `DICE_MIN_SCALE` at 15+. Recalibrate
  the two constants for `@drdreo/dice-box-threejs`'s `baseScale` (default 100).
  Exact values are empirical, fixed by the Decision 6 visual-check task and
  recorded here. The curve's invariants (monotonic non-increasing, `count<=6`
  returns base, floored at min, non-positive treated as 1) and its unit tests are
  unchanged in intent; only the numeric expectations move.
- Rationale: The shrink-to-fit behavior is still needed; only the units changed.
- Trade-offs: `diceAnimationScale.test.ts` numeric expectations updated.

### Decision 5: Replace the engine types; delete `types/dice-box.d.ts`

- Chosen: `@drdreo/dice-box-threejs` ships `types/index.d.ts` with `DiceBox`,
  `DiceConfig`, `DiceResults`, `DiceSet`, `DiceResult`. Import those directly in
  `useDiceAnimation.ts` and `reconcileDiceFaces.ts`. Delete
  `types/dice-box.d.ts` (the ambient declaration for the old type-less engine).
  If `tsconfig` `types` / `typeRoots` referenced it, update accordingly.
- Rationale: Real published types beat a hand-maintained ambient stub.
- Trade-offs: none.

### Decision 6: Legibility — `+N more` on the existing readout + a re-tuned canvas band

- Chosen:
  - `DiceRollOverlay`'s `StaticRollResult` already renders every
    `built.breakdown` die (and both percentile faces). Add: above
    `DICE_ANIM_CAP`, render the first `DICE_ANIM_CAP` dice plus a `+N more`
    indicator (`N = breakdown.length - DICE_ANIM_CAP`); the total stays
    `built.total` for the whole pool. Below the cap, behavior is unchanged.
  - Re-check the canvas band `max-w` / `max-h` against the new engine's camera /
    `baseScale` so 15 dice settle inside the clear zone above the modal and do
    not obscure the modal or the readout; adjust the Tailwind classes if needed,
    keeping the fixed margin above the modal (n047 layout preserved).
  - Exact `baseScale` / container values fixed by a task that captures desktop
    (1280px) and mobile (375px) screenshots of `2d12`, `2d20`, `d%`, `15d6` and
    records the constants here.
- Alternatives considered:
  - A brand-new readout component: rejected — one already exists and is on every
    reveal path; only the large-pool cap is missing.
  - Per-die numbered glyphs on the canvas dice: rejected — invisible on the
    disabled / unsupported / mismatch-skip paths.
- Rationale: The issue's readability half is already largely solved; this
  finishes it and keeps the DOM readout as the safety net.
- Trade-offs: `DiceRollOverlay.test.tsx` gains a large-pool `+N more` case.

## Risks / Trade-offs

- Risk/trade-off: The spike (Decision 1) finds `@drdreo/dice-box-threejs` cannot
  reliably force faces in this app's setup.
  - Impact: Engine swap still happens (the `@` engine is still better maintained
    and the Babylon one is abandoned for this use), but "land on correct faces"
    reverts to detect-and-skip.
  - Mitigation: Decision 3 guard is the floor; Change Control updates the
    proposal; the reconciliation + legibility work still ships value.
- Risk/trade-off: Main-thread physics jank on large pools.
  - Impact: Dropped frames while 15 dice tumble.
  - Mitigation: 15-die cap, `iterationLimit`, `ROLL_TIMEOUT_MS`, `15d6`
    visual-check.
- Risk/trade-off: Asset self-hosting misconfigured → textures 404.
  - Impact: Untextured or failed animation.
  - Mitigation: committed copy step; `assetPath` unit-asserted; engine failure
    falls through to the instant path.
- Risk/trade-off: Single-maintainer fork pinned at `1.1.0`.
  - Impact: Upstream fixes may lag.
  - Mitigation: exact pin, MIT, vendored assets; reconciliation guard bounds any
    regression to "skip the tumble"; follow-up issue to re-evaluate.
- Risk/trade-off: `useDiceAnimation.test.ts` / `toDiceBoxNotation.test.ts` mock
  and expectation churn.
  - Impact: Test rewrite effort.
  - Mitigation: contract preserved, so `GlobalDiceFab` / overlay tests are
    largely untouched; only the engine-boundary mocks change.

## Rollback / Mitigation

- Rollback trigger: Post-merge, the animation is visually broken, the result
  modal fails to appear for some users, the reconciliation guard suppresses
  correct animations, or the new engine crashes on some devices, and a forward
  fix is not immediate.
- Rollback steps: Revert the change's squash-merge commit. The reverted state
  restores `@3d-dice/dice-box` and the prior (wrong-faces but non-crashing)
  animation. Users can also tick "Disable animation" in the dice panel for an
  immediate personal workaround.
- Data migration considerations: None — no persisted data, schema, API, or RNG
  changes; `BuiltRoll` values are untouched.
- Verification after rollback: `GlobalDiceFab` renders; rolling shows the result
  modal with the correct total and per-die readout; existing
  `DiceRollOverlay` / `useDiceAnimation` / `toDiceBoxNotation` / `GlobalDiceFab`
  unit suites and the dice E2E smoke pass on the reverted commit.

## Operational Blocking Policy

- If CI checks fail: treat as blocking. Diagnose from the failing job logs, fix
  on the working branch, re-run the project's unit / integration / E2E / build
  commands locally, commit, push, re-check. Never merge with red required checks;
  never use `--admin`.
- If security / code-quality checks fail (Verity gate, Codacy): fix the finding —
  that is the default. Only `verity waive` a finding when a human has explicitly
  accepted that specific risk in this change's review, citing the source in
  `--reason`. Never waive on the agent's own judgement.
- If required reviews are blocked/stale: after opening the PR and passing the
  `pr-review-toolkit:review-pr` gate (zero findings), enable auto-merge
  (`gh pr merge --auto --merge`) and let GitHub merge when conditions are met.
  Poll review threads and CI autonomously; address each, push, repeat.
- Escalation path and timeout: if `pr-review-toolkit:review-pr` findings persist
  after three or more review-fix-push iterations with no progress, or a CI
  failure resists three fix attempts, stop, report the remaining items to the
  user, and wait for human guidance. If the Decision 1 spike is inconclusive
  after its time box, stop and bring the findings to the user before proceeding
  past Decision 3.

### Decision 1 spike — RESOLVED 2026-08-30

Drove `@drdreo/dice-box-threejs@1.1.0`'s self-contained ESM bundle (three +

Chromium (SwiftShader WebGL), assets served from a static `assetPath: '/assets/'`

| Case | Result |
|---|---|
| `d6 / d8 / d10 / d12 / d20`, single and 15-die same-size pools with per-die `@` values | ✅ **Every settled value matches the `@` target.** (`reason` is occasionally reported as `"natural"` instead of `"forced"` on a die that nonetheless landed on the right value — so reconciliation must compare **values**, never `reason`.) |

| `clearDice()` + drop reference + new `DiceBox` + roll again | ✅ Clean; render loop stops, context frees, reuse works in one page. |
| **Mixed die sizes in one `roll()` string (`"2d20@14,2+1d6@5"`)** | ❌ **The promise never resolves (hangs).** The `+` is not a group separator here. |
| Mixed die sizes via `roll(group0)` then `await box.add(group1)` per size, then `box.getDiceResults()` | ✅ Combined `DiceResults.sets` carry the correct forced values for every group; `total` is correct. |
| **`d4@n`** | ❌ **`@` is ignored entirely** — the die rolls naturally (wrong value), and with a high `iterationLimit` the roll sometimes **hangs**. The d4 face-map / point-up geometry in this engine does not support forcing. |
| `assetPath` | Must end in `/`; textures resolve as `<assetPath>textures/<name>.webp`. |

**Path forward (assumption A1 partially holds):**

1. **`toDiceBoxNotation` returns an ordered list of per-die-size group notations,
   not a `+`-joined string.** `useDiceAnimation` calls `box.roll(groups[0])` then
   `await box.add(groups[i])` for each remaining group, then reconciles against
   `box.getDiceResults()`.
2. **d4 groups are emitted as plain `Nd4` (no `@`).** Forcing a d4 is impossible
   and risks a hang; a plain d4 roll is fast and safe. Any pool containing a d4
   therefore reconciles as a mismatch and reveals through the instant path
   (Decision 3) — no misleading d4 tumble is shown, the correct result always is.
   d6–d20 and percentile pools animate correctly.
3. **`iterationLimit` is kept modest** (≈2000) and every `roll()` / `add()` call
   stays inside `ROLL_TIMEOUT_MS` as a backstop against any residual hang.
4. Reconciliation compares settled **values** per die-size multiset; `reason` is
   informational only.

Decision 2 is updated: `toDiceBoxNotation` returns `string[]` (or a typed
`DiceBoxRollPlan`), and `useDiceAnimation` drives `roll` + `add`. Decision 3 is
unchanged in intent — it is now load-bearing for d4 pools, not just defensive.
