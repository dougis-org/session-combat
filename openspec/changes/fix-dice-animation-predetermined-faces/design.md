## Context

- Relevant architecture:
  - `lib/dice/useDicePoolState.ts` — `buildRoll()` / `buildPercentileRoll()`
    produce a `BuiltRoll` whose `breakdown: { sides, value }[]` and
    `percentileFaces?: [number, number]` are the authoritative predetermined
    faces. `rolls` / `total` are derived from them. Generated by the centralized
    secure RNG (n116); persisted before presentation (n134).
  - `lib/dice/toDiceBoxNotation.ts` — pure map from `BuiltRoll` to a
    `@3d-dice/dice-box` roll argument. Today: `"<count>d<sides>@<v1>,<v2>,…"`
    (groups joined `+`; percentile `2d10@<tens>,<ones>`). Caps the animated
    subset at `DICE_ANIM_CAP = 15` via `animatedDiceCount()`.
  - `lib/dice/useDiceAnimation.ts` — lazy `import('@3d-dice/dice-box')` (WebGL
    probed once per mount), `new DiceBox({ container, assetPath, theme, scale })`,
    `box.init()`, then `await box.roll(toDiceBoxNotation(built))`. Bounded by
    `IMPORT_TIMEOUT_MS` / `INIT_TIMEOUT_MS` / `ROLL_TIMEOUT_MS`. Splits
    persistent failures (latch `status: 'unsupported'`, log once) from transient
    per-roll failures (tear down the box, keep the 3D path armed). `run()`
    resolves `true` when the tumble is over and this run is current, `false`
    when the reveal is another run's job. **`box.roll()`'s return value is
    discarded at `lib/dice/useDiceAnimation.ts:173`.**
  - `lib/dice/diceAnimationScale.ts` — `DICE_BASE_SCALE = 12`,
    `DICE_MIN_SCALE = 6`; linear shrink from 6 dice to `DICE_ANIM_CAP` dice.
  - `lib/components/dice/DiceRollOverlay.tsx` — body-level portal (n047).
    Centered vertical stack: bounded canvas band
    (`w-[90vw] max-w-[480px] h-[38vh] max-h-[340px]`) above a result modal that
    shows `built.formula` and `built.total` only. Modal gated on
    `animationSettled` / `animationStatus === 'unsupported'` / a
    `MODAL_REVEAL_FALLBACK_MS` fallback (n136). Remounted per roll via `key`.
  - `lib/components/GlobalDiceFab.tsx` — owns roll state; awaits
    `animation.run()` and passes `animationSettled` to the overlay; renders the
    inline `formula → [rolls] = total` line.
  - `types/dice-box.d.ts` — ambient module declaration (dice-box ships no
    types). Models `roll(notation: string): Promise<DiceBoxResult[]>` where
    `DiceBoxResult` has `sides`, `value`, `groupId`, `rollId`.
  - `tests/e2e/dice-roll-animation.spec.ts` — smoke: asserts the result modal
    total equals the inline total; never inspects a die face.
- Dependencies:
  - `@3d-dice/dice-box@^1.1.4` (latest published; no upgrade path). Documented
    surface: string notation (`2d6+3`), object notation
    (`{ qty, sides, modifier, theme }`), array notation, `roll()`, `add()`,
    `reroll(dieOrDice, { remove, newStartPoint })`, `clear()`,
    `onRollComplete(results)`. The public docs do **not** describe an `@`
    predetermined syntax — the exact supported mechanism for forcing faces is
    what Decision 1 resolves.
  - React 18 client components; Tailwind; `react-dom` `createPortal`;
    Playwright for E2E.
- Interfaces/contracts touched:
  - `toDiceBoxNotation(built): string` — return type and/or shape changes to
    whatever dice-box honors (may become `DiceBoxRollSpec` object/array).
  - `useDiceAnimation.run()` — unchanged `Promise<boolean>` contract, but
    internally it now inspects `box.roll()`'s results and can classify a
    face mismatch as a transient failure.
  - `DiceRollOverlayProps` — the overlay reads `built.breakdown` /
    `built.percentileFaces` to render the per-die readout (no new required
    prop; `built` is already passed).
  - `types/dice-box.d.ts` — extended.
  - `openspec/specs/global-dice-fab/spec.md` — MODIFIED requirement.

## Goals / Non-Goals

### Goals

- The physical dice in the 3D animation settle showing the predetermined faces
  for the roll, for every supported die type and for percentile — OR, when the
  engine cannot achieve that, the misleading tumble is not shown or held and the
  correct result is revealed instead.
- `box.roll()`'s settled results are inspected and reconciled against the
  predetermined faces; a mismatch is a transient per-roll condition that never
  latches the whole session to the instant path.
- The animated dice are visually larger than today, and the result modal shows a
  per-die readout that is legible at 375px viewport width — independent of the
  WebGL canvas.
- E2E coverage asserts settled die faces (not just the aggregate total).
- No change to `built.total` / `built.rolls`; no new randomness or network.

### Non-Goals

- Upgrading / forking dice-box.
- Cross-client frame accuracy.
- Animating more than 15 dice.
- New themes, sound, or camera work.
- Non-WebGL animation; changing `disableAnimation` resolution.

## Decisions

### Decision 1: Establish the real predetermined-value API with a bounded spike before locking the mechanism

- Chosen: The first implementation task is a time-boxed spike (deps installed in
  the worktree) that reads `node_modules/@3d-dice/dice-box` source + its shipped
  README and determines exactly how `1.1.4` accepts forced per-die results.
  Candidate mechanisms, in preference order:
  1. Object/array roll notation carrying a per-die `value` (e.g.
     `box.roll([{ qty: 1, sides: 12, value: 4 }, …])` or a `rolls` array).
  2. `box.roll(randomNotation)` then, for each die whose settled `value` differs
     from target, `box.reroll(die, { remove: true })` — up to one bounded pass.
  3. The `@3d-dice/dice-parser-interface` / `@3d-dice/dice-roller-parser` layer
     that the dice-box README points at for advanced notation, if it is already
     a transitive dependency or can be added self-contained.
  The spike's finding is recorded as a short note appended to this design's
  "Open Questions" resolution and drives Decisions 2 and 3. If none of
  1–3 reliably works, the change proceeds with Decision 4 only (detect + skip)
  and `proposal.md` is updated per Change Control.
- Alternatives considered:
  - Assume the `@` syntax is correct and just tune physics: rejected — the bug
    reproduces on nearly every roll across all die types, which is not a
    physics-space symptom, and the public docs do not mention `@`.
  - Ship the reconciliation guard only, never attempt correct faces: rejected as
    the primary plan — it leaves the animation permanently cosmetic-but-wrong
    when it could be correct; kept as the documented fallback (Decision 4).
- Rationale: Every downstream decision depends on the mechanism; guessing it
  produced the current bug.
- Trade-offs: Adds a spike step before code; bounded to keep momentum.

### Decision 2: `toDiceBoxNotation` emits the spike-confirmed forced-value form; behavior contract unchanged

- Chosen: Rewrite `toDiceBoxNotation` to return the argument shape dice-box
  honors (Decision 1 outcome — expected to become a typed `DiceBoxRollSpec`
  object/array rather than a string). It stays pure, keeps grouping by die size
  in first-seen order, keeps the percentile `2 × d10` mapping (`00` → face
  `10,10`), and keeps the `DICE_ANIM_CAP = 15` truncation. `animatedDiceCount()`
  is unchanged. If the spike selects Decision 1 option 2 (reroll loop), this
  function still produces the target-face list and the loop logic lives in
  `useDiceAnimation`.
- Alternatives considered:
  - Keep returning a string and change only the separator/token: rejected unless
    the spike shows a string form actually works.
  - Move face selection into `useDiceAnimation`: rejected — keeping the pure
    mapping isolated preserves unit-testability and the single
    predetermined-source invariant.
- Rationale: One pure, well-tested seam from `BuiltRoll` to the engine argument.
- Trade-offs: A shape change ripples into `types/dice-box.d.ts` and the existing
  `toDiceBoxNotation` unit tests (rewritten, not deleted).

### Decision 3: Reconcile `box.roll()` results against the predetermined faces inside `useDiceAnimation`

- Chosen: Capture the `DiceBoxResult[]` from `box.roll()` (no longer discarded).
  Build the expected multiset of `{ sides, value }` from
  `toDiceBoxNotation`'s input (the capped `breakdown`, or the two percentile
  d10 faces). Compare **per die-size group as multisets**, not positionally,
  to tolerate dice-box reordering. Percentile results are mapped through an
  explicit `0 ↔ 10` normalization before comparison.
  - Match → resolve `run()` as today (`true`, reveal the modal).
  - Mismatch → treat as a **transient per-roll failure** (same class as a
    malformed-notation roll error, per n125): `console.warn` once per mounted
    hook, tear the box down without bumping the run token, and resolve `run()`
    `true` so `GlobalDiceFab` reveals the result immediately through the normal
    path (not the long fallback). `status` stays `idle` — the next roll still
    attempts the 3D path.
  - If Decision 1 option 2 (reroll) is chosen, the single bounded reroll pass
    happens before this classification; only a still-mismatched result after the
    pass is a transient failure.
- Alternatives considered:
  - Wire dice-box `onRollComplete` into the overlay: rejected — the overlay does
    not own the `DiceBox`; keeping reconciliation in the hook preserves the
    single-instance invariant (n140).
  - Positional comparison: rejected — dice-box may return groups/dice in a
    different order, causing false positives.
  - Latch `unsupported` on mismatch: rejected — a mismatch is per-roll, not an
    engine capability loss; latching would needlessly disable a feature that
    works for other rolls.
- Rationale: Uses data the library already returns; makes "we showed you a wrong
  tumble" impossible without extra awaits.
- Trade-offs: A correct-but-unusual settle (e.g. dice-box returning an extra
  cocked-die result) could trip the guard; mitigated by multiset comparison and
  by only comparing the first `animatedDiceCount()` dice per group.

### Decision 4: Documented fallback if faces cannot be forced — detect and skip, never show a wrong tumble

- Chosen: If Decision 1 finds no reliable mechanism, `toDiceBoxNotation` reverts
  to plain random notation (`"2d12"`), `useDiceAnimation` still performs the
  Decision 3 reconciliation, and **every** roll is therefore classified as a
  potential mismatch — so the hook compares and, on mismatch, skips straight to
  the instant reveal (transient path). The net effect: no 3D tumble is shown
  when it would be misleading, the correct result still appears immediately, and
  the legibility work (Decision 5) still lands. `proposal.md` Scope is updated
  per Change Control to mark "land on correct faces" as not achieved.
- Alternatives considered:
  - Show the random tumble anyway with a disclaimer: rejected — undermines the
    fairness perception the issue is about.
  - Disable the animation feature entirely: rejected — it still works as an
    unpredictable-but-honest effect for users who enable it knowing faces are
    cosmetic; but default behavior is to skip on mismatch.
- Rationale: "Correct or absent" is the only acceptable pair for a dice tool.
- Trade-offs: Users may rarely see the 3D animation until dice-box gains the
  feature or is replaced (tracked as a follow-up, out of scope here).

### Decision 5: Legibility — bigger dice band + a canvas-independent per-die readout in the result modal

- Chosen:
  - Raise `DICE_BASE_SCALE` (target: die face ≈ the modal total's `text-4xl`
    order) and retune `diceAnimationScale`'s floor so 15 dice still fit; widen
    the canvas band's `max-w` / `max-h` within the centered stack, keeping a
    fixed margin above the modal (n047 layout preserved).
  - Add a per-die result row to the result modal in `DiceRollOverlay.tsx`,
    rendered from `built.breakdown` (or `built.percentileFaces`): large text,
    styled like the inline `formula → [rolls] = total` line, shown together with
    the total. It is plain DOM text — legible regardless of WebGL, the canvas
    band, or a reconciliation skip. Above the 15-die cap it shows the animated
    subset plus a `+N more` affordance; the total remains the full-pool total.
  - Exact `scale` / container values are empirical: a task captures desktop
    (1280px) and mobile (375px) screenshots and records the chosen constants.
- Alternatives considered:
  - CSS `transform: scale()` on the canvas: rejected — blurs the raster, breaks
    pointer math (same as #596 Decision 1).
  - Per-die numbered glyphs instead of text: deferred to the Open Question;
    default is text.
  - Put per-die values only on the canvas dice: rejected — invisible on the
    unsupported / disabled / mismatch-skip paths, which is most of the point.
- Rationale: The issue asks for both "dice show the rolled values" and "big
  enough to read"; a DOM readout satisfies the readability requirement
  unconditionally while the physics fix satisfies the fidelity requirement when
  the engine cooperates.
- Trade-offs: Reopens the #596 size/layout tuning; bounded by explicit
  visual-check tasks and the independent DOM readout as the safety net.

## Proposal to Design Mapping

- Proposal element: Repair the predetermined-value path so dice-box settles on

  - Design decision: Decision 1 (spike), Decision 2 (`toDiceBoxNotation` shape),

## Non-Functional Requirements Mapping

- Requirement category: reliability
  - Requirement: The result modal MUST always become visible after a roll,
    regardless of animation, WebGL, or reconciliation outcome, and no path may
    leave the user without the result.
  - Design element: Decision 3 (mismatch → prompt reveal), Decision 4, existing
    n136 fallback timeout (unchanged).
  - Acceptance criteria reference: specs NFAC "Reliability / Recovery behavior";
    cross-references functional scenario "Face mismatch reveals the result
    without showing a wrong tumble".
  - Testability notes: fake-timer tests — mismatched results reveal well before
    `MODAL_REVEAL_FALLBACK_MS`; a never-resolving `box.roll()` still reveals at
    the fallback.
- Requirement category: performance
  - Requirement: Reconciliation adds no network request and no additional
    awaited engine round-trip beyond an optional single bounded reroll pass;
    total animation time stays within the existing `ROLL_TIMEOUT_MS` budget.
  - Design element: Decision 3 (synchronous multiset compare), Decision 1
    option 2 bound.
  - Acceptance criteria reference: specs NFAC "Performance / Latency budget".
  - Testability notes: unit test asserts reconciliation makes no `fetch` and, in
    the no-reroll design, no second `box.roll` / `box.reroll` call; timing
    assertion that a mismatch resolves `run()` synchronously after the first
    `roll()` resolves.
- Requirement category: operability
  - Requirement: A face mismatch is observable to developers exactly once per
    mounted hook (no per-roll log spam) and is distinguishable from a
    malformed-notation roll error and from a persistent unsupported condition.
  - Design element: Decision 3 (dedicated warn message, `loggedRef`-style
    once-guard, `status` untouched).
  - Acceptance criteria reference: specs NFAC "Operability / Diagnostics".
  - Testability notes: unit test asserts a distinct `console.warn` string for
    mismatch vs the existing `console.error` for a thrown roll, and that a
    second mismatch in the same mount does not log again.

## Risks / Trade-offs

- Risk/trade-off: The spike (Decision 1) finds no reliable forced-face
  mechanism in dice-box 1.1.4.
  - Impact: "Land on correct faces" goal not met; animation effectively skipped
    on mismatch until dice-box changes or is replaced.
  - Mitigation: Decision 4 path; the reconciliation guard and legibility work
    still ship real value; Change Control updates the proposal.
- Risk/trade-off: Raised `scale` clips or the settled dice overlap the modal
  (#596 layout concern reopened).
  - Impact: Total or on-canvas dice partly hidden.
  - Mitigation: The per-die readout and total are DOM text above/independent of
    the canvas; explicit desktop + mobile visual-check tasks; retain the
    fixed-margin-above-modal layout; `DICE_MIN_SCALE` floor tested.
- Risk/trade-off: Multiset reconciliation false-positive on an unusual but
  correct settle (extra cocked-die result, duplicate `rollId`).
  - Impact: A valid animation is skipped.
  - Mitigation: Compare only the first `animatedDiceCount()` dice per size
    group; unit-test dice-box's documented `DiceBoxResult` shape; the failure
    mode is "skip to correct result", never "show wrong result".
- Risk/trade-off: Rewritten `toDiceBoxNotation` shape breaks other callers.
  - Impact: Type errors / broken import.
  - Mitigation: `toDiceBoxNotation` has exactly one production caller
    (`useDiceAnimation`); tests updated in the same change; `tsc --noEmit` in
    Validation.

## Rollback / Mitigation

- Rollback trigger: Post-merge, the animation is visually broken, the result
  modal fails to appear for some users, or the reconciliation guard suppresses
  animations that were actually correct, and a forward fix is not immediate.
- Rollback steps: Revert the change's squash-merge commit. The reverted state
  restores the prior (wrong-faces but non-crashing) animation. Users can also
  tick "Disable animation" in the dice panel for an immediate personal
  workaround while a fix is prepared.
- Data migration considerations: None — no persisted data, schema, API, or RNG
  changes; `BuiltRoll` values are untouched.
- Verification after rollback: `GlobalDiceFab` renders; rolling shows the result
  modal with the correct total; existing `DiceRollOverlay` / `useDiceAnimation` /
  `toDiceBoxNotation` / `GlobalDiceFab` unit suites and the dice E2E smoke pass
  on the reverted commit.

## Operational Blocking Policy

- If CI checks fail: treat as blocking. Diagnose from the failing job logs, fix
  on the working branch, re-run the project's unit / integration / E2E / build
  commands locally (per `README.md` / `AGENTS.md` / `CLAUDE.md`), commit, push,
  re-check. Never merge with red required checks; never use `--admin`.
- If security / code-quality checks fail (Verity gate, Codacy): fix the finding —
  that is the default. Only `verity waive` a finding when a human has explicitly
  accepted that specific risk in this change's review, citing the source in
  `--reason`. Never waive on the agent's own judgement.
- If required reviews are blocked/stale: after opening the PR and passing the
  `pr-review-toolkit:review-pr` gate (zero findings), enable auto-merge
  (`gh pr merge --auto --merge`) and let GitHub merge when conditions are met.
  Poll review threads and CI autonomously; address each, push, repeat.
- Escalation path and timeout: if `pr-review-toolkit:review-pr` findings persist
  after three or more review-fix-push iterations with no progress, or a CI
  failure resists three fix attempts, stop, report the remaining items to the
  user, and wait for human guidance. If the Decision 1 spike is inconclusive
  after its time box, stop and bring the findings to the user before proceeding
  past Decision 4.
